## 6. Team-owned technical work: recommendations, not owner decisions

The following should be investigated by the contributors without asking the owner to select assertion formulas or debug code. Where a repair changes the semantics rather than merely enforcing a promised property, propose a new configuration and report the difference.

- TW-01 - Accounting: derive totals from holdings or authoritative unit records; independently verify sender debits, recipient credits, declared creation, and consistency between reported and derived totals. Trace: S1 ChatGPT/Copilot audit sections.

- TW-02 - Authorization: verify input permissions independently of output status. Separate debiting, issuance, receipt acceptance, and world-change authority. Do not confuse an omitted gate with an intentionally unrestricted model. Trace: S1 all authority discussions.

- TW-03 - Completion: enforce the promised unit type, uniqueness, encumbrance, provenance, recipient, and quantity conditions. Exact versus at-least delivery is a contract choice to declare; the checker must enforce the selected one. Trace: S1 Copilot and Perplexity.

- TW-04 - Receipts and event order: bind receipts to obligations and requests; validate issuance after the appropriate completion event. A global receipt flag and final balances cannot by themselves prove historical ordering. Trace: S1 Claude/ChatGPT/Copilot.

- TW-05 - Request integrity: detect same-ID/different-payload conflicts; distinguish same-ID retries, new-ID repeat demand, and multiple requests for one obligation. Trace: S1 Claude/Copilot.

- TW-06 - Recovery: implement only the declared partial-delivery policy. Preserve progress, rollback, and compensation traces separately. Replace hard-coded fixture thresholds with request quantities before generalizing. Trace: S1 Claude/Copilot.

- TW-07 - Checker challenge: include deliberately defective records and implementations. Report which were detected, which were missed, which are equivalent or invalid mutants, and why. Assertion count is not a mutation-detection score or a proof of completeness. Trace: S1 ChatGPT/Copilot/Grok/Perplexity.

- TW-08 - Reproduction: preserve original v0.1 artifacts; publish repaired code, fixtures, generated outputs, environment details, and hashes under a new revision. Link each finding to its code/checker/configuration. Trace: S1 ChatGPT/Claude/Copilot.

- TW-09 - Publication hygiene: inspect visible text and embedded hyperlinks; replace temporary signed links in corrected public editions. Do not infer account compromise from an expired URL alone. Preserve an appropriate original record without recirculating temporary access material. Trace: S1/S2.

- TW-10 - Artifact availability: verify missing-file claims at the same commit/path; distinguish full read, partial inspection, metadata listing, and inaccessible content. Do not ask the owner to adjudicate changing snapshots from memory. Trace: S1 Perplexity and S2 conflicting results-file reports.

- TW-11 - Outcome interpretation: preserve assumed, derived, executed, and externally observed categories. Treat code reruns as reproduction of synthetic rules, not real QC capability validation. Trace: S1 all substantive audit responses.

- TW-12 - Comparison: retain distinct architectures. Use identical configurations for reproduction, different configurations for architectural comparison, and explicit scope for observational equivalence. Trace: S1 ChatGPT/Copilot/Grok/Perplexity.
